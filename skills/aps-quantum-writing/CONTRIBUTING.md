# Contributing

Thank you for helping improve scientific clarity and reproducibility.

## Start with an issue

Report a concrete problem, the relevant file, the affected journal/article type, and the evidence supporting the proposed correction. For typography, include the official source or a DOI, source version, and page number. For a plot defect, provide a minimal synthetic example rather than confidential research data.

This is a source-available project with restricted redistribution, not an unrestricted open-source contribution model. Private changes for permitted use are allowed. Before publicly posting patches, translations, modified skill bundles, or a pull request containing substantial project material, obtain the author's written permission and agree how the contribution may be licensed. An issue can describe a defect without republishing a modified copy of the skill.

GitHub's platform permissions remain governed by its terms. A platform fork does not by itself grant broad permission to market a renamed release or redistribute it elsewhere. Preserve author and third-party notices.

## Quality expectations for agreed contributions

- Preserve the three branches and progressive loading of references.
- Tie new writing rules to a demonstrated failure or a reliable source.
- Separate official requirements, observed article practice, and editorial defaults.
- Preserve scientific conditions, uncertainty, and source versions.
- Use English for public instructions and documentation.
- Add a regression case before a behavior change, and run the whole applicable test suite.
- Render visual changes at their final physical size; inspect actual pixels.
- Keep example data synthetic and labeled, or supply lawful, documented data provenance.
- Never include credentials, private paths, unpublished manuscripts, or copied journal PDFs/images without appropriate permission.

## Review checklist

Explain the problem and smallest fix; list files affected; include actual test results; identify checks that were not run. Do not describe passing numeric tests as proof of visual quality, scientific correctness, or journal acceptance.

See [validation](docs/VALIDATION.md), [provenance](docs/PROVENANCE.md), and [third-party notices](THIRD_PARTY_NOTICES.md).
